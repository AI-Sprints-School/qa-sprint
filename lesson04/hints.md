# Задание 2.2. Лестница подсказок к запросам 1–5

Подсказки разрешены и списыванием не считаются. Открывайте столько
ступеней, сколько нужно, и ставьте над своим запросом в `sql.md`
пометку уровня HTML-комментарием: `<!-- самостоятельно -->`,
`<!-- по заготовке -->` или `<!-- по готовому -->`. На странице файла
комментарий не виден, в коде остаётся.
Пометка нужна не для оценки: по ней видно, где буксуют все,
и это чинится в материалах, а не в студентах.

Запросы 1–5 вы пишете после двух пополнений из задачи 1, поэтому
в выводе запросов 2 и 3 наверху уже ваши сегодняшние строки.

**У запроса 6 подсказок нет ни на одной ступени.** Он собирается
из конструкций первых пяти, и именно он проверяет главный результат задания.

Схема базы всегда открыта на боковой панели консоли. Две таблицы:

- `wallets` — `id`, `owner_login`, `display_name`, `balance`, `currency`,
  `tariff`, `fee_percent`, `is_demo`, `created_at`;
- `operations` — `id`, `wallet_id`, `type`, `amount`, `comment`, `created_at`.

Строки в SQL пишутся **одинарными** кавычками: `'student-07'`. Двойные
кавычки Postgres читает как имя колонки.

## Запрос 1. Свой кошелёк

Нужна одна строка: номер вашего кошелька, логин, баланс и тариф.
Полученный номер — ваш `wallet_id`, он понадобится в каждом следующем запросе.

<details>
<summary>Ступень 1. Где искать</summary>

Таблица `wallets`. Колонки: `id`, `owner_login`, `balance`, `tariff`.
Отобрать нужно строку, у которой `owner_login` равен вашему логину —
тому самому, которым вы входите в «Кошелёк».

</details>

<details>
<summary>Ступень 2. Заготовка с пропусками</summary>

```sql
SELECT id, owner_login, balance, tariff FROM wallets WHERE ___ = ___;
```

Пропущены колонка отбора и значение. Значение — строка, и кавычки у неё
одинарные.

</details>

<details>
<summary>Ступень 3. Готовый запрос с разбором</summary>

```sql
SELECT id, owner_login, balance, tariff
FROM wallets
WHERE owner_login = 'student-07';
```

- `SELECT` — какие колонки показать. Звёздочка вернула бы все девять,
  а нужны четыре.
- `FROM` — из какой таблицы.
- `WHERE` — условие отбора строк. Без него вернутся кошельки всей когорты.

Подставьте свой логин вместо `student-07`.

</details>

## Запрос 2. Свои последние операции

Пять свежих строк журнала вашего кошелька: номер, тип, сумма, комментарий, время.

<details>
<summary>Ступень 1. Где искать</summary>

Таблица `operations`. Колонки: `id`, `type`, `amount`, `comment`,
`created_at`, `wallet_id`. Ваш `wallet_id` вы получили запросом 1.
«Свежие» — значит отсортированные по времени, «пять» — значит с ограничением.

</details>

<details>
<summary>Ступень 2. Заготовка с пропусками</summary>

```sql
SELECT id, type, amount, comment, created_at
FROM operations
WHERE wallet_id = 42
ORDER BY ___ ___
LIMIT ___;
```

Пропущены поле сортировки, направление и число строк. Число 42 замените
своим `wallet_id`.

</details>

<details>
<summary>Ступень 3. Готовый запрос с разбором</summary>

```sql
SELECT id, type, amount, comment, created_at
FROM operations
WHERE wallet_id = 42
ORDER BY created_at DESC
LIMIT 5;
```

- `ORDER BY created_at` — сортировка по времени создания.
- `DESC` — по убыванию, сверху самые свежие. Без `DESC` сортировка идёт
  по возрастанию, наверху окажутся самые старые записи, и свежая строка
  в `LIMIT` не попадёт.
- `LIMIT 5` — вернуть не больше пяти строк.

</details>

## Запрос 3. Фильтр по типу

Только пополнения вашего кошелька.

<details>
<summary>Ступень 1. Где искать</summary>

Та же таблица `operations`. Колонка `type` принимает три значения:
`TOPUP` — пополнение, `WITHDRAW` — списание, `FEE` — комиссия.
Условий отбора теперь два, и оба должны выполняться одновременно.

</details>

<details>
<summary>Ступень 2. Заготовка с пропусками</summary>

```sql
SELECT id, type, amount, created_at
FROM operations
WHERE wallet_id = 42 ___ type = ___
ORDER BY created_at DESC;
```

Пропущены связка двух условий и значение типа. Значение — строка,
кавычки одинарные, регистр важен.

</details>

<details>
<summary>Ступень 3. Готовый запрос с разбором</summary>

```sql
SELECT id, type, amount, created_at
FROM operations
WHERE wallet_id = 42 AND type = 'TOPUP'
ORDER BY created_at DESC;
```

- `AND` соединяет два условия: строка попадёт в вывод, только если верны оба.
- Условие по `wallet_id` не убирается никогда: без него вы смотрите
  на журнал всей когорты, и консоль упрётся в тайм-аут.

</details>

## Запрос 4. Сортировка с ограничением

Три самые крупные операции вашего кошелька по сумме.

<details>
<summary>Ступень 1. Где искать</summary>

Та же таблица. «Самые крупные» — это сортировка по `amount`, а не
по времени. Направление выбирается так, чтобы наверху оказались
большие числа.

</details>

<details>
<summary>Ступень 2. Заготовка с пропусками</summary>

```sql
SELECT id, type, amount, created_at
FROM operations
WHERE wallet_id = 42
ORDER BY ___ ___
LIMIT ___;
```

</details>

<details>
<summary>Ступень 3. Готовый запрос с разбором</summary>

```sql
SELECT id, type, amount, created_at
FROM operations
WHERE wallet_id = 42
ORDER BY amount DESC
LIMIT 3;
```

- Сортировать можно по любой колонке, не обязательно по той, что стоит
  первой в `SELECT`.
- `LIMIT` применяется после сортировки, а не до неё: сначала база
  выстраивает все строки по убыванию суммы, потом отдаёт три верхние.

</details>

## Запрос 5. Соединение двух таблиц

Операции вашего кошелька рядом с данными самого кошелька: логин, тариф
и процент комиссии `fee_percent`.

Под запросом обязательна отдельная строка обоснования: **по каким двум
колонкам идёт соединение и почему именно по ним**. Формулировка
«соединяю таблицы, чтобы получить тариф» обоснованием не считается —
в ней нет ответа про поля.

<details>
<summary>Ступень 1. Где искать</summary>

Нужны обе таблицы сразу. В `operations` есть колонка `wallet_id` —
это ссылка на строку в `wallets`. В `wallets` соответствующая колонка
называется `id`. Соединение идёт по паре «ссылка — то, на что она
ссылается», а не по совпадению сумм или дат.

</details>

<details>
<summary>Ступень 2. Заготовка с пропусками</summary>

```sql
SELECT o.id, o.type, o.amount, w.owner_login, w.tariff, w.fee_percent
FROM operations o
JOIN wallets w ON ___ = ___
WHERE o.wallet_id = 42
ORDER BY o.created_at DESC
LIMIT 10;
```

Пропущены обе колонки соединения. `o` и `w` — короткие имена таблиц,
чтобы не писать их полностью в каждой строке.

</details>

<details>
<summary>Ступень 3. Готовый запрос с разбором</summary>

```sql
SELECT o.id, o.type, o.amount, w.owner_login, w.tariff, w.fee_percent
FROM operations o
JOIN wallets w ON w.id = o.wallet_id
WHERE o.wallet_id = 42
ORDER BY o.created_at DESC
LIMIT 10;
```

- `JOIN ... ON` — как связать строки двух таблиц. Условие `w.id = o.wallet_id`
  говорит: строка операции относится к тому кошельку, чей `id` записан
  у неё в `wallet_id`.
- Без `ON` (например, если перечислить таблицы через запятую) база
  соединит каждую строку с каждой, и строк в ответе окажется больше,
  чем в обеих таблицах вместе.
- `WHERE` после соединения по-прежнему нужен: он оставляет только ваш кошелёк.

</details>
