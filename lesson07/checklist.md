# Чек-лист ревью AI-теста: пять вопросов

Ни запуск кода, ни знание Python для него не нужны.

**Вопрос 1. Упадёт ли этот тест, если фича сломается?**
Главный. Назовите конкретную порчу продукта, пройдите тест глазами с ней.
Покраснел — тест настоящий. Остался зелёным — теста нет, есть его форма.

**Вопрос 2. Откуда взялось ожидаемое значение?**
Посчитано человеком заранее и записано числом — или получено из того же
кода, который проверяется? Ожидание, снятое с проверяемой функции или
с объекта после действия, совпадёт с результатом всегда.

**Вопрос 3. Есть ли в тесте настоящее утверждение?**
Найдите строку `assert`. Строки нет — теста нет, есть вызов. Строка есть,
но проверяет всегда истинное (объект существует, значение не пустое,
что-то равно самому себе) — тоже нет.

**Вопрос 4. Тест проверяет обещание продукта или устройство кода?**
Обещание: «после пополнения на 100 баланс вырос на 100». Устройство:
«внутреннее поле называется так-то и хранит строку такого формата».

**Вопрос 5. Совпадает ли имя теста с тем, что он проверяет?**
Прочитайте имя, потом последнюю строку. Расходятся — верить надо ассерту,
имя врёт.

---

**Порядок применения на практике: 3 → 2 → 5 → 4.** Механические проверки
идут первыми, они отсеивают половину дефектов до всякого размышления.
Вопрос 1 — итоговый: им вердикт доказывается.

**Вердикт без указания на строку — не вердикт.** В ревью пишут не «тест
плохой», а «строка 4: ожидание снято с объекта после действия».
